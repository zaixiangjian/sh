# beifenhebing.sh 使用与数据目录说明

## 最重要：单文件可以在新服务器使用

**`beifenhebing.sh` 是可独立分发的单文件管理脚本，可以在新服务器部署使用。只需复制这一份 `.sh`，不需要提前复制配套 `.py` 文件。**

将脚本复制到新服务器后，以 root 执行：

```bash
bash beifenhebing.sh
```

首次运行会从脚本内嵌源码自动释放辅助程序，创建需要的运行目录；缺少系统依赖时自动检查安装。网站、论坛及本地归档管理组件不需要从 GitHub 下载。系统依赖安装可能需要联网，SSH/S3 传送需要能连接配置的远端。

**单文件可用指程序可以独立部署，不代表自动携带原服务器的任务、凭据、SSH 私钥或备份。** 新服务器可在菜单中添加新任务；要迁移已有任务，还需迁移 `/home/备份/data/` 及相关归档/读取目录和私钥，并核对路径与权限。对应备份源必须实际存在，例如 `/home/web` 或 `/var/discourse`。

验证范围：曾将单独一份 `.sh` 放入无预先存在辅助程序的隔离环境，验证自动释放、源码编译和菜单退出。此测试不等于已在另一台真实服务器完成安装、真实远端传送及恢复测试。

## 启动与单文件部署

主脚本：`/root/yingyong/beifenhebing.sh`。

```bash
bash /root/yingyong/beifenhebing.sh
```

管理脚本内嵌运行组件源码。新服务器只需复制此 `.sh` 文件，使用 root 运行；启动时自动在 `/root/yingyong/` 释放所需 Python 辅助程序，不从 GitHub 下载这些组件。缺少系统依赖时，软件包安装仍可能需要联网。生成的任务执行文件依赖已释放的本地引擎及任务注册表，不是独立部署脚本。

## 配置、状态与锁的位置

统一存放在：`/home/备份/data/`。

```text
/home/备份/data/
├── website/       # 1 网站备份
├── forum/         # 2 论坛全量备份
├── generated/     # 3 论坛生成备份传送
├── local-sync/    # 99 同步模式
├── local-keep/    # 99 不删除远端模式
└── migration-backup-…/  # 迁移前配置备份
```

各功能子目录保存任务注册信息、任务配置与执行文件、SSH/S3 凭据、传送状态、SSH 主机信任记录、运行锁及业务日志。凭据为权限保护的明文，不是加密存储；不要公开、上传至公开仓库或通过聊天发送。

实际 `.tar.gz` 归档保存在添加任务时指定的本地备份路径，不统一移动进 `data/`。论坛内部生成的原始备份目录也与配置目录分开。99 递归扫描排除 `/home/备份/data/`，避免把运行数据纳入归档传送。

## 菜单与任务关系

- **1. 网站备份（/home/web）**：网站目录热备、SSH 最新备份传送、S3 最新备份传送。
- **2. 论坛备份（/var/discourse）**：论坛全量目录热备、SSH/S3 传送及从 `/home` 检测归档恢复。恢复需精确输入小写 `yes`，执行前须先停止论坛容器及数据库；恢复成功后按提示使用 `kejilion.sh` 重建。
- **3. 论坛生成备份传送**：读取 Discourse 自己生成的备份，自动识别网站名，校验稳定的最新归档、复制到所选保存目录后传送；不重新打包、不清理原始备份。
- **99. 备份本地*.tar.gz**：递归读取指定路径（默认 `/home/备份`）内全部 `.tar.gz`，保留相对目录结构，不传配置或凭据，不删除本地文件。同步模式在上传与校验成功后删除专用远端内本地已不存在的 `.tar.gz`；保留模式不删除远端。

1、2 的添加备份任务要求填写文件名前缀，新归档使用 `<前缀>-YYYY-MM-DD-HHMMSS.tar.gz`，时间为 UTC。其 SSH/S3 传送任务自动继承备份目录及前缀，允许修正读取路径。旧无前缀任务仍按原命名规则识别，不自动改名。

子菜单的测试连接、执行和删除只管理对应分类的任务。删除任务使用菜单 **9**，保留实际归档及稳定锁文件。不要直接删除整个 `data/` 或锁文件。

## 依赖与连接检测

基础运行依赖包括系统 Python 3、SSH 客户端、flock、cron；密码认证使用 sshpass，S3 使用 boto3。脚本其他保留功能还可能需要 curl、wget、rsync 等。安装过的依赖检测正常时不重复提示。

主菜单只读取本地任务数量并修复调度，不主动检测 SSH/S3 连接。进入对应子菜单才探测实际连接，重绘复用会话缓存；菜单 **7. 测试连接** 可刷新。已保存 SSH 主机指纹不等于服务器当前在线，首次信任需独立核对指纹。

## 定时任务块与后台修复

打开主菜单时，对 1、2、3 及 99 的两个模式分别静默检查并修复所属 cron 块和后台服务：有配置任务才启用对应调度，无任务不新增。只处理本脚本所属块，保留其他 cron；成功不提示，失败仍提示错误。

cron 分钟调度器检查任务是否到期，不代表每分钟重新打包。小时任务按 UTC 周期边界与指定分钟执行；天任务使用配置的 UTC 小时、分钟及间隔。传送监控使用独立后台服务，具有重启与健康检查逻辑。

自动修复可能启动已有任务后台服务；服务检测到待传归档时仍会按任务规则连接远端。这与菜单是否主动探测连接是两回事。

## 锁与并发

不同分类、99 的同步/保留模式使用独立注册目录、服务及 cron 标记。任务操作使用稳定 `run.lock`，调度修复、worker 单例及日志轮转也有各自锁。进程退出时内核释放锁，文件存在不代表锁被占用。

不通过删除锁文件解除占用，以免新旧进程锁住不同 inode。不同任务可以并行，但独立任务锁不能保护两个任务共用的远端清理目标：应给各任务使用独立远端目录或 S3 key 前缀，尤其 99 同步模式。

## 传送、校验与保留

1、2、3 的传送任务只选择对应规则的最新完整归档，成功且未变化时跳过，不补传历史文件。默认等待连续 5 秒无变化，失败间隔 60 秒，总尝试次数默认 3（含首次），以任务配置为准。99 是递归全部归档传送，不同于最新单文件模式。

S3 默认 8 MiB 阈值开始分片、每片 8 MiB、并发 2；Cloudflare 超时/WAF 或源站限制仍可能导致失败。前缀保留清理只在上传并真实读回 SHA256 校验成功后执行；版本化桶历史版本需另配生命周期规则。

99 同步模式要求专用远端路径。读取目录为空时不触发远端清空，校验失败不把该轮传送标记完成。99 SSH 校验/清理命令需要远端 Python 3。

网站和论坛全量备份均为不停服务的热备，不保证正在写入的数据库一致性；不能把论坛目录热备等同于 Discourse 官方逻辑数据库备份。

## 日志轮转

各分类目录的 `operations.log` 采用 2 MiB 轮转，保留 5 个历史文件及当前文件。日志记录有限的事件/状态或异常类型，不记录密码、S3 Key 或完整配置。日志轮转使用文件锁保护。

systemd/journald 日志仍按系统级设置管理，不受上述业务文件轮转规则限制。

## 迁移与备份建议

只复制 `.sh` 可部署程序，但不会自动迁移已有任务、凭据及归档。迁移已有运行数据需保留：

1. `/home/备份/data/`；复制时保护凭据权限。
2. 各任务指定的归档目录和原始备份读取路径。
3. 私钥认证使用的 SSH 私钥及必要系统配置。

迁移或恢复运行数据前先停止相关后台服务，避免状态文件和归档并发写入。`migration-backup-…/` 是旧布局迁移时保留的配置备份，不是最新任务状态副本；含敏感配置，应妥善保护。不要误删后再依赖它恢复最新任务。
